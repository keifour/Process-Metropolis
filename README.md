# Process Metropolis · 数字生态大都会

把真实系统进程变成一座可以旋转、探索和管理的赛博城市。Node.js 采样，Three.js 渲染，Electron 提供 Windows 桌面窗口。

## Windows 桌面版

在 [Releases](https://github.com/keifour/Process-Metropolis/releases) 下载 `Process-Metropolis-0.3.0-windows-x64.exe`，双击运行。支持 Windows 10/11 x64，无需 Node.js、浏览器或 WSL。首次启动会解压内置运行时，关闭窗口即停止监控服务。

程序未进行商业代码签名，Windows 可能提示未知发布者。下载校验值见 Release 中的 `SHA256SUMS.txt`。

## v0.3 的变化

- 建筑与碎片批量绘制，减少 CPU 提交和 GPU 状态切换。100 座建筑的基础场景实测绘制调用从约 222 次降到 6 次；选中与碎片特效仍不超过 12 次。
- 硬件模式按屏幕刷新节奏渲染，目标最高 60 FPS。自动画质会调整分辨率，软件显卡有独立的降载策略。目标帧率不是所有设备上的保证值，可在工具栏查看实际 FPS。
- 增量更新进程列表，保留滚动位置和键盘焦点；按时间平滑建筑高度与相机移动。
- 真实 CPU / 内存趋势、单进程历史、进程生命周期事件和资源压力预警。
- 内存天际线与 CPU 热力视图、相机聚焦和环绕、安静模式。
- 置顶、筛选、三种排序、CSV 导出、快捷键与画质偏好记忆。

趋势只记录本次会话，最多保留约两分钟 / 60 个采样点。事件日志保留最近 80 条。图表不会生成应用启动之前的数据。

## 从源码运行

需要 Node.js 22.12 或更新版本。支持 Windows x64、Linux 与 macOS。

```sh
npm ci
npm start
```

在服务所在电脑打开 `http://127.0.0.1:3000`。可通过 `PORT=3001 npm start` 更换端口；Windows PowerShell 中使用 `$env:PORT=3001; npm start`。

桌面窗口与测试：

```sh
npm run desktop
npm test
```

Windows 原生采样使用随包附带的 .NET/Win32 辅助程序，不依赖 PowerShell 或 WMI。源码测试和桌面启动会自动使用 Windows 自带的 .NET Framework 4 编译器生成辅助程序。辅助程序常驻并以行协议通信，避免每次采样重启进程。

## 操作

| 操作                    | 效果                                     |
| ----------------------- | ---------------------------------------- |
| 拖动 / 滚轮             | 旋转 / 缩放城市                          |
| 点击建筑或列表          | 查看进程、父 PID 和资源历史              |
| 双击建筑 / F            | 聚焦选中进程                             |
| H                       | 重置视角                                 |
| /                       | 搜索名称或 PID                           |
| 空格                    | 切换动态效果；按钮聚焦时保留原生键盘操作 |
| Escape / 点击城市空白处 | 取消进程选择                             |
| ☆                       | 置顶当前进程，避免排序时失去它           |
| ⇩                       | 导出当前筛选后的进程为 UTF-8 CSV         |

城市最多显示 100 个资源占用较高的进程；选中的存活进程会被纳入城市。侧栏保留全部可见进程（采样命令本身除外）。建筑高度表示当前映射的资源占用，颜色表示负载；高 CPU 可触发轻微地面震动，高内存压力增加雾效。关闭动态效果可消除环境运动。排序变化不会被当成进程退出。

## Windows 构建与发布

在 Windows 上：

```sh
npm ci
npm run dist:win
```

产物在 `dist/`。GitHub Actions 先执行测试与桌面预检，再构建，并实际启动打包目录和最终免安装 EXE，检查进程采样、WebGL、选择、绘制预算和进程保护。推送与包版本一致的 `v*` 标签后，只有全部检查成功才会上传并发布 Release。

发布回执、测试及启动报告保存在 `release-reports/<分支或标签>` 分支。Release 包含 SHA-256 校验值和两份 Windows 启动报告。

## 指标、权限与限制

监控的是 **Node.js 服务所在机器**。云端服务无法读取访客电脑进程；本机桌面应用读取本机进程。容器中只看到容器可见的进程。

Linux CPU 使用相邻采样的进程时间差，Windows 使用 .NET 累计进程时间差，单进程按单核 100% 计算，多线程可超过 100%。Windows 首个采样 CPU 为 0，Linux 首个采样与 macOS 使用 `ps` 的指标。顶部 CPU 按逻辑核数归一化。物理内存是系统 `total - free`，包含可回收缓存，雾效不能用于确诊内存泄漏。

默认以普通用户权限运行，不提供提权。只允许结束当前用户的非关键进程；Windows 另限制当前非系统会话。结束前再次检查启动身份、所属用户和权限，保护 PID 1、系统关键进程、应用自身及其父子进程。强制结束使用 Unix SIGKILL / Windows 原生终止，可能丢失未保存内容，不能完全消除系统级竞争窗口。

服务只绑定回环地址，并验证 Host、Origin 和会话令牌。不应通过公网代理暴露。桌面界面开启沙箱，不开放 Node.js，也不加载外部网页。Three.js、字体回退与界面资源离线可用，无外部 API、数据库或密钥要求。
